## Findings and decisions

- Blocking issues and resolution: none found in local, candidate, tag, or registry checks.
- Accepted nonblocking issues, owners and follow-up: Read the Docs built stable from the immutable `v0.5.1` tag. That tag's documentation was generated before publication and retains the pre-release label and 0.5.0 install examples. The main branch documentation is being corrected in a follow-up so `latest` is current; the stable alias still points to the exact release tag.
- Unsupported patterns and trusted assumptions: unchanged from 0.5.0; see [ownership limitations](../ownership.md).
- Performance baseline and candidate comparison: no new benchmark run for this corrective patch; 0.5.0 performance evidence is retained for unchanged workloads. No performance claim is added.
- Required migration and changed default diagnostics: baseline fingerprints include the exact engine version; review and regenerate a 0.5.0 baseline when upgrading to 0.5.1. Ownership checks remain opt-in and existing default exit policy is unchanged.
- Reused evidence: 0.5.0 ownership and concurrency qualification at [0.5.0 release evidence](0.5.0-evidence.md), applicable because this patch narrows unsupported container-boundary timing without changing the qualified ownership or TaskGroup model. The two new ownership regressions and complete current candidate suites were run again.
