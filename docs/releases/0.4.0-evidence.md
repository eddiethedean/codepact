## Qualification evidence

The [assertion mapping and reproduction harness](../planning/phases/0.4/evidence/qualification-2026-11-10/README.md)
map V04-01–26 to independent semantic, policy, presentation, interoperability,
input-limit, incremental, repair and synthetic-corpus controls. Exact source and
artifact identities and final CI runs are recorded below. The retained source run passed 480 Rust tests, 39 Python tests, 24 release controls, 23 configuration cases, eight consumer controls and all synthetic/static-tool controls. The raw archive contains 127 CLI records and 72 corpus reports; the successful full local check includes a second run from the packaged crate.

The new controls corrected generator result-use classification, baseline
whitespace/same-line site identity, exact-limit physical-input alias counting,
human-output byte bounds and broken stderr handling. Baseline algorithm 5 caches
canonical token/site anchors and retains resolved contract identity. Adoption
report/baseline construction rejects cancelled, inspection-only and lifecycle-only
results that claim unexecuted must-use rules. Snapshot identity includes analyzed
scope and rule/fingerprint revisions. The JSON schema independently checks that
scope claim, and the reference consumer verifies versions, current source,
selected-file attribution, counts, framing and stale/limited/error handling.

## Cold installed CLI comparison

Seven new-process samples per version/workload on the same Apple M4 Pro host,
with published macOS arm64 0.3 wheel SHA-256
`5704430ee59651b60f3776e6040aa197f9fcb8599ac9a6bf1edcbb501277b4d3` and the
exact 0.4 candidate wheel installed above. The initial source fixtures match the
retained Rust lifecycle and cleanup/async generators. Both versions used
`check --root <fixture> --python-version 3.11 --json <files>`, with `--no-config`
for 0.4, and default advisory behavior. Timings include launch and captured
JSON; each report hash is stable across repeats and every input hash is unchanged.
Canonical diagnostic code/message/certainty/trust/completion and all locations
agree. Lifecycle workloads preserve the unresolved helper boundary as well as
TP1001; async workloads retain possible cleanup and unknown cancellation;
qualified sync cleanup is clean. Advisory exits are 1 for lifecycle and 0 for
sync/async, with incompleteness preserved. The sample record with input/output
hashes has SHA-256 `2aaab1c0f01874703bff067f93df25b2ab6afb5ea7e0dd9cd43ed843dd845318`.

Dense CLI reports cost more: 1,000 findings take 108.480 ms instead of
37.799 ms (2.87×), with peak RSS nearly unchanged. The matching in-process
cold check improves about 9%, so this is distinct from a semantic-analysis
regression. The schema 2 CLI builds per-finding identity and policy evidence,
scans source prefixes for anchors, and emits about 67% more JSON on that
workload. These costs explain the additional work; the measurement does not
isolate each cost. The G4 review includes this tradeoff, the warm and retained
memory regressions above, and the absence of an absolute latency SLA. Per-file
anchor indexing is a follow-up opportunity for dense output.
