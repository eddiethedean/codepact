## Candidate automation evidence

On 2026-11-07, `uv run --locked make check` passed for this candidate source tree
on CPython 3.14.3, macOS 26.5.2 ARM64. `cargo test --workspace --locked`
passed 59 library, 51 CLI, 60 fixture, 26 lifecycle regression and 157 phase
tests; all 14 Python tests passed. Formatting, workspace check, Clippy, Python
typing/lint, identifier-table checks, package builds and clean-install smokes,
dependency audits, Rust 1.96 checks/package test and install smoke, inspector
behavior, documentation links and the warnings-as-errors docs build passed.
V03-03 checks 60 three-level finalizer combinations and adds nested awaited
finalizers across fallthrough, return and raise with exact cancellation spans.
V03-05 adds a known handler-expression raise that still crosses `finally` and
discharges the resource duty with complete supported-subset coverage.
V03-07 checks nested finally replacement with four exact acquisition-to-exit
witnesses. V03-14 checks outer-loop break and continue transfers after inner-loop
exhaustion with exact duty spans. V03-26 combines coroutine-capture and async
exit-partition exhaustion inside nested while/for paths.

The exact-candidate Quality run 42445940360 passed Rust quality, dependency audit,
documentation and Python 3.11–3.14 jobs. The exact-candidate Release run built
and smoke-tested all eight native CLI wheels, built the pure helper wheel and
both source archives, ran the Cargo publish dry run, and passed artifact
inventory and metadata validation. The downloaded bundle passed the local
11-artifact inventory check and strict Twine checks. The pure helper wheel and
macOS ARM64 CLI wheel installed offline together in a clean CPython 3.14.3
virtual environment; `verify_installed_package.py` and
`smoke_release_cli.py --binary` passed their helper import, CLI and lifecycle
checks. The GitHub secret name `PYPI_API_TOKEN` is configured, and the `pypi`
environment has no protection rules or required reviewers. The tag-only
publisher jobs consume that secret; this manual run skips them and does not
exercise the credential. These results establish automation behavior only;
they do not pass technical release gates.

Controlled `contextlib` runtime outcomes and source hashes are recorded in the
[conformance record](../planning/phases/0.3/contextlib-conformance.md). The
[performance record](../planning/phases/0.3/performance.md) measures candidate
workloads after optimizing resolved-call state transfer, source-span lookup
and the bounded exit-partition worklist. At 1,000 resources, cold and edit
medians are 0.46×–0.72× the accepted 0.2 baseline; the 250-resource medians are
0.71×–1.04×, with the warm no-op sample slightly above baseline and edit
samples below it. Single-resource samples are small and noisy. The maintainer's
G4 review remains pending. No latency threshold has been defined by the phase
plan.
