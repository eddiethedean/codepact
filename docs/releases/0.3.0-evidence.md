## Candidate automation evidence

On 2026-11-01, `uv run --locked make check` passed on candidate
`136e5df4175ca6829c192311ec399729c74b2ee9` on CPython 3.14.3, macOS 26.5.2
ARM64. `cargo test --workspace --locked` passed 59 library, 51 CLI, 60
fixtures, 26 lifecycle regression and 144 phase tests; all 14 Python tests
passed. Formatting, workspace check, Clippy, Python typing/lint, identifier-table
checks, package wheel/sdist builds and install smokes, dependency audit, MSRV,
inspector behavior, documentation links and the warnings-as-errors docs build
passed. The Python quality suite also passed locally on CPython 3.11.15,
3.12.13 and 3.13.16. Exact-candidate Quality run 41318398681 passed Rust
quality, dependency audit, documentation and Python 3.11–3.14 jobs. Added
V03-03/07 regressions assert exact nested cleanup raise completions/spans,
branching and nested `finally` replacement duties/outcomes, and close-before-
handoff through reviewed `closing`. V03-05 asserts the actual exit and spans
when an unmatched raise is replaced in `finally`, and separate possible
constructor and explicit-raise witnesses for unresolved custom inheritance.
It also verifies that rebinding `BaseException` to `ValueError` cannot hide
an unmatched `RuntimeError` raise; handler matching now requires the built-in
name to remain unshadowed. V03-09 covers Owned helper
close/return/leak/raise outcomes and Borrowed no-delegation return/raise;
V03-10 checks reviewed context cleanup on return, break and continue. V03-13
covers escaped bound methods; V03-14/15 cover `while`-`else`,
unconditional `continue`, generated break/continue `else` routing and static
loops through 16 iterations. V03-01 asserts that unsupported custom `__new__`
effects keep prior duties possible and visible as a boundary; V03-22 checks
pass/close/raise body edits against fresh results and reruns only the affected
flow query.
V03-17 asserts exact asynchronous close cancellation snapshots, and V03-18
records that a `BaseException` handler catches cancellation while preserving
the conservative uncertain lifecycle state. The earlier V03-01/02/06/10/19/
20/23 cases continue to cover constructor failure, Borrowed aliases, shared
raise grouping, uncertain alias/callback/scheduler duties, root-set
invalidation, and moved acquisition/annotation spans. The V03-16 loop/alias
budget case retains every candidate duty as possible.

The exact-candidate Release run 41318401619 built and smoke-tested all eight
native CLI wheels, built the pure helper wheel and both source archives, ran the
Cargo publish dry run, and passed full artifact inventory and metadata
validation. The verified bundle was downloaded and rechecked locally with
`scripts/verify_release_distributions.py` (eight CLI wheels, one pure wheel and
two source archives) and `twine check --strict` (all 11 artifacts passed). The
pure helper wheel and macOS ARM64 CLI release wheel were installed together in
a clean temporary virtual environment; helper API imports passed and
`scripts/smoke_release_cli.py --binary` passed its version, help, and lifecycle
checks. Artifact hashes are listed below. The workflow was dispatched
on the branch; all publication jobs were skipped.

The downloaded exact-candidate bundle was verified locally with the required
11-artifact inventory, strict Twine checks, offline installation into a clean
CPython 3.14.3 environment, helper API imports, and the installed CLI lifecycle
smoke. The source CLI tutorial runs on this candidate produced the expected one
definite synchronous leak and cancellation-possible asynchronous findings.
Controlled `contextlib` runtime outcomes and source hashes are recorded in the
[conformance record](../planning/phases/0.3/contextlib-conformance.md). These
results establish automation behavior only; they do not constitute maintainer
semantic acceptance or pass a release gate.

The [performance record](../planning/phases/0.3/performance.md) measures the
candidate workloads on the release host after optimizing resolved-call state
transfer, source-span lookup and the bounded exit-partition worklist. At 1,000
resources, cold and edit medians are 0.46×–0.72× the accepted 0.2 baseline; the
250-resource medians are 0.71×–1.04×, with the warm no-op sample slightly above
baseline and edit samples below it.
Single-resource samples are small and noisy. The maintainer's G4 review remains
pending. No latency threshold has been defined by the phase plan.
