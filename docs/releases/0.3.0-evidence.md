## Candidate automation evidence

On 2026-11-08, candidate commit
`5c559c253102750a71111325363fac298c57816a` passed
`uv run --locked make check` locally on CPython 3.14.3, macOS 26.5.2 ARM64.
`cargo test --workspace --locked` passed 60 library, 51 CLI, 60 fixture, 26
lifecycle regression and 166 phase tests (363 Rust tests total); all 21 Python
tests passed. The matrix-integrity check confirms that all 26 V03 IDs appear in
both tables, all 60 named test references are declared Rust tests, and qualified
symbols resolve to Rust functions. Its four unit tests cover missing rows,
stale references and non-test functions substituted for tests. Release-evidence
tests confirm that one accountable maintainer can fill every review role and
that passed gates require the maintainer's name and a valid ISO date.
Formatting, workspace check, Clippy, Python typing/lint, identifier-table
checks, package builds and clean-install smokes, dependency audits, Rust 1.96
checks/package test and install smoke, inspector behavior, documentation links
and the warnings-as-errors docs build passed.
V03-04 adds `src/db.rs::exceptional_close_outcome_matrix_keeps_duties_isolated`,
which checks Closed/Open/Preserve/Unknown exceptional outcomes together and
asserts isolated certainty, exact acquisition spans and model provenance.
V03-03 checks 60 three-level finalizer combinations and adds nested awaited
finalizers across fallthrough, return and raise with exact cancellation spans.
V03-05 adds tuple-handler matching, preserves unknown matching for qualified
handler attributes, and avoids exact routing for shadowed constructor names,
wildcard imports, conditional module-level exception rebinding, pattern
captures, nested class `global` writes and conditional type aliases. The last
three cases retain possible unmatched-raise duties and incomplete coverage. An
unrelated conditional binding preserves exact built-in handler routing;
invalid tuple handler types remain boundaries while a successful close in
`finally` discharges the duty.
V03-13 checks that an unrelated local resource is not escaped by a no-argument
unknown call. V03-18 checks a successful synchronous close after caught
cancellation while retaining the cancellation boundary.
V03-07 checks nested finally replacement with four exact acquisition-to-exit
witnesses. V03-14 checks outer-loop break and continue transfers after inner-loop
exhaustion with exact duty spans. V03-26 combines coroutine-capture and async
exit-partition exhaustion inside nested while/for paths.
