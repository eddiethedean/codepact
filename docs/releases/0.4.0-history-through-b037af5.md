## Development after the frozen candidate

The current development tree fixes a reproduced baseline correctness defect:
changing a resource's `closed_by` contract or rebinding its imported class could
leave an old cleanup finding suppressed. Fingerprint algorithm 4 now includes
resolved contract/callable identity, preserves that evidence across incremental
queries, and rejects algorithm 3 baselines. Baseline generation requires the
internal resolved facts from a fresh analysis, rather than deserialized public
reports. The [regression controls](../planning/phases/0.4/validation.md#current-candidate-test-references)
cover changed cleanup contracts, changed resolved imports, harmless declaration
moves, fresh/reused parity and missing identity evidence.

The [retained before/after counterexample](../planning/phases/0.4/evidence/baseline-contract-2026-11-10/README.md) reproduces the defect with the exact old artifact. [V04-02 configuration controls](../planning/phases/0.4/evidence/config-qualification-2026-11-10/README.md) now pass technically, and [14 adoption CLI workloads](../planning/phases/0.4/evidence/adoption-cli-2026-11-10/README.md) retain seven optimized samples each. These controls do not complete the other matrix rows, session/memory operational requirements or A05.

The source changes invalidate the previous distribution freeze. The candidate
and workflow results below describe `317ef90`, not the current development tree.
A new freeze and affected qualification are required before tagging.
