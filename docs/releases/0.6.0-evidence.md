## Findings and decisions

- All technical gates passed; the accountable maintainer reviewed and approved the candidate on 2026-11-15. Merge PR #22 and push the `v0.6.0` tag to begin publication.
- The earlier mutable-worktree performance records are not comparable: they identify a base commit but not the changed source hash or an isolated build directory. The retained candidate record uses fresh builds in separate directories for `v0.5.1` and candidate `1da46b6`. The retained workload comparison shows at most +2.5% cold/edit time and +3.6% peak RSS; state and exclusive location-only edits still require nearly a full recheck.
- Unsupported patterns and trusted assumptions are documented in the [specification](../planning/phases/0.6/specification.md) and [limitations](../limitations.md). The claims remain an experimental lifetime/protocol preview; they do not establish race freedom, deadlock freedom or general thread/process safety.
- Required migration and changed default diagnostics: advanced contracts are opt-in; see the [CLI](../cli.md), [ownership guidance](../ownership.md) and [0.6 release notes](../release-notes.md).
- Reused evidence: 0.5.1's published release record applies to unchanged prior-release behavior only; exact-candidate suites were rerun locally.

## Analyzer architecture evidence

- AM01–AM06 and the Rust parser/AST/Salsa dependency inventory remain inherited from the published [0.5.1 release evidence](0.5.1-evidence.md); phase 0.6 adds the advanced semantic and flow contracts described in the specification.
- The candidate passed Rust formatting, compilation, Clippy, workspace tests, dependency audits, MSRV validation, source-archive tests, local package installs, docs checks and the exact-candidate CI replay. The direct CLI/API parity regression also passed its focused test.
- Query reuse and invalidation controls are in [db.rs](../../crates/codepact/src/db.rs). The phase06 protocol provider test asserts three initial flow-query executions, then two after a provider edit, and equality with a fresh result. Existing session tests cover location/model/settings updates and cancellation recovery.
- Budget controls exist for lifecycle flow, aliases, objects, AST declarations, request inputs and pending coroutine records. TaskGroup scheduled records share the 128-coroutine cap; the unreachable second counter was removed. The new evidence exercises limit, overflow, known-finding preservation, source-edit recovery and unrelated-query reuse.
- Persistent-cache evidence is not applicable to this phase; no persistent cache is introduced. Editor parity is not part of the delivered 0.6 scope.
