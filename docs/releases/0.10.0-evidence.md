### Performance comparison

An optimized clean `d853c04` checkout and the published 0.9.0 checkout were
built with Rust 1.96.0 and compared on macOS 26.5.2 ARM64. The capture alternated
the order of 24 adjacent process pairs for each inherited
workload with seven trials per process. The table reports the median
paired timing change and the difference in maximum observed peak RSS.

| Inherited workload | Cold | Unchanged | Affected edit | Unrelated edit | Peak RSS change |
| --- | ---: | ---: | ---: | ---: | ---: |
| State | -1.09% | -2.32% | -0.27% | -0.11% | +0.81 MiB |
| Exclusive access | +0.04% | -0.42% | +0.04% | +1.83% | +0.19 MiB |
| Executor | +3.84% | -0.02% | +3.92% | +2.16% | +2.03 MiB |
| Installed manifest | +0.52% | +1.20% | +0.26% | +0.54% | +0.41 MiB |
| Review | -0.63% | -0.06% | -0.83% | -0.37% | 0.00 MiB |
| Work-result observation | 0.00% | -0.62% | +0.62% | -0.40% | +0.39 MiB |

The largest relative timing increase was 3.92% for an affected executor
edit (59 µs). The largest absolute timing increase was 0.194 ms for an
affected work-result edit. The executor's largest observed peak RSS rose
from 17.31 to 19.34 MiB. Its paired median RSS increase was 3.21%.

## Release decision and publication

Preflight on 2026-11-18 found the 0.10.0 version unused on both PyPI projects
and crates.io. The remote `v0.10.0` tag was absent. The expected repository
secret names were configured. The `pypi` deployment environment accepted all
refs. The [release plan](../planning/releases.md) describes
publication on both Python projects and crates.io.

Keep the candidate commit in the ancestry of the tag and retain its source
tree. The [release checker](../../scripts/check_release_evidence.py) permits
only this evidence file to differ between the candidate and the tag. When
the maintainer signs off, record that decision and run the checker on the
proposed tag commit.

```sh
python3 scripts/check_release_evidence.py 0.10.0 --tag-commit HEAD
```
