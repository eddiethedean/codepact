# 0.8 — Ecosystem integration, editor services and persistent caching

Status: **Planned**. Target first release: **0.8.0**. No gate is currently marked passed.
Owner: maintainer to assign before implementation. Legacy mapping: M5 integration portion / implementation Phase 5.

## Outcome

Deliver editor services and persistent reuse on the already qualified incremental analyzer, together with supported ecosystem integrations.

## Entry gate

The preceding minor phase's required gates are accepted, or an explicit scope/dependency amendment has been recorded in the root roadmap. Reuse its supported corpus and baseline metrics.
Before work begins, turn the work packages below into issues with owners and acceptance evidence. Apply the [common release gates](../release-gates.md).

## Work packages

1. Extend the 0.1 Salsa session with a versioned persistent-cache layer, validated reuse, safe rejection and measured memory limits.
2. Deliver the [linting and IDE diagnostics plan](../linting-and-editors.md): a shared language server, thin VS Code and JetBrains clients, and verified Neovim/Emacs recipes using the same analysis engine and configuration resolver as the CLI.
3. Expand reviewed third-party models and selected Pydantic/FastAPI/dataclass compatibility fixtures.
4. Validate a Protocol-based bridge; add novel trait machinery only through a separately accepted RFC.
5. Maintain and requalify the typepact-cli native wheel matrix and pure typepact dependency contract selected in D015, together with source builds and the Cargo distribution. Preserve lightweight helper imports and installed-command behavior during cache/editor integration.
6. Deliver [AI-agent integration](../ai-agent-integration.md) AI04–AI05: a local read-only MCP adapter for checks, contracts and explanations, plus qualified shell/IDE/MCP client workflows sharing CLI semantics.

Concurrency work: Publish the versioned concurrency-model matrix and qualify CLI/editor/agent and cache parity. Keep unsupported process/thread handoffs visible. Any multiprocessing semantic model needs a separate reviewed proposal covering serialization, start methods, handles and worker failure. Follow [CS06](../concurrency.md) for the exact supported subset and evidence.

## Required exit gates

- [ ] **E01** — Cached and fresh analysis produce equal facts and diagnostics across source, dependency summary, configuration, target-version and engine-version changes.
- [ ] **E02** — Corrupt or incompatible caches are discarded safely; parallel execution preserves deterministic diagnostic ordering.
- [ ] **E03** — CLI and editor agree on codes, locations and certainty; document changes and cancellation do not publish stale diagnostics.
- [ ] **E04** — Every supported integration names pinned upstream versions and has a maintained fixture; metadata is not silently interpreted as runtime validation.
- [ ] **E05** — The pure typepact wheel resolves its matching typepact-cli dependency; each native CLI wheel supplies a working command on its declared platform. Both source archives and the optional Cargo installation remain usable.
- [ ] **E06** — Publish cold/warm latency and peak-memory measurements. Investigate regressions over 10% median on repeated controlled runs before acceptance.
- [ ] **CS06** — Complete the phase requirements in the [concurrent resource safety plan](../concurrency.md); retain valid, invalid and unsupported-boundary fixtures and fresh/reused parity for the claimed subset.

Use the [shared architecture](../architecture.md) and [migration/query specification](../analyzer-migration.md). These obligations extend the existing phase gates.
