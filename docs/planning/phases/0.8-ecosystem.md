# 0.8 — Ecosystem integration and incremental analysis

Status: **Planned**. Target first release: **0.8.0**. No gate is currently marked passed.
Owner: maintainer to assign before implementation. Legacy mapping: M5 integration portion / implementation Phase 5.

## Outcome

Make repeated analysis and supported integrations reliable.

## Entry gate

The preceding minor phase's required gates are accepted, or an explicit scope/dependency amendment has been recorded in the root roadmap. Reuse its supported corpus and baseline metrics.
Before work begins, turn the work packages below into issues with owners and acceptance evidence. Apply the [common release gates](../release-gates.md).

## Work packages

1. Add content/dependency/configuration keyed caches and deterministic invalidation.
2. Implement an editor integration using the same analysis engine and configuration resolver as the CLI.
3. Expand reviewed third-party models and selected Pydantic/FastAPI/dataclass compatibility fixtures.
4. Validate a Protocol-based bridge; add novel trait machinery only through a separately accepted RFC.
5. Complete portable wheel delivery for the published platform matrix and source-build coverage.

## Required exit gates

- [ ] **E01** — Cached and fresh analysis produce equal facts and diagnostics across source, dependency summary, configuration, target-version and engine-version changes.
- [ ] **E02** — Corrupt or incompatible caches are discarded safely; parallel execution preserves deterministic diagnostic ordering.
- [ ] **E03** — CLI and editor agree on codes, locations and certainty; document changes and cancellation do not publish stale diagnostics.
- [ ] **E04** — Every supported integration names pinned upstream versions and has a maintained fixture; metadata is not silently interpreted as runtime validation.
- [ ] **E05** — Every advertised wheel installs and runs the CLI on a clean supported platform; source artifacts build with the documented prerequisites.
- [ ] **E06** — Publish cold/warm latency and peak-memory measurements. Investigate regressions over 10% median on repeated controlled runs before acceptance.

## Evidence to retain

Invalidation matrix, editor/CLI parity report, framework matrix, platform installation logs and reproducible benchmark results.
Complete a [release evidence record](../release-evidence-template.md) for the exact candidate revision. Link each gate to test results, fixtures, decisions or reviewed reports. A checkbox without evidence is pending.

## Hold and recovery policy

Limit the published support matrix to verified combinations. If an integration or platform is deferred, update scope and user documentation before calling the release complete.
A failed required gate blocks the tag. Patch releases fix behavior within the published scope; moving a required feature out of scope requires a documented plan amendment.

## Deferred scope

Broad trait coherence, associated types and general higher-ranked lifetimes remain research.

## Release review

Review the phase gates together with G1–G8, publish limitations and changed diagnostics, then authorize the release tag separately. 0.8.x follow-ups retain these obligations and add regression evidence for each fix. See the [root roadmap](../../../ROADMAP.md).
