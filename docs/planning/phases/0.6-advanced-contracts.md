# 0.6 — Exclusive access, typestate and effects

Status: **Planned**. Target first release: **0.6.0**. No gate is currently marked passed.
Owner: maintainer to assign before implementation. Legacy mapping: M4 / implementation Phase 4.

## Outcome

Extend the shared model with finite state machines and modeled exclusivity.

## Entry gate

The preceding minor phase's required gates are accepted, or an explicit scope/dependency amendment has been recorded in the root roadmap. Reuse its supported corpus and baseline metrics.
Before work begins, turn the work packages below into issues with owners and acceptance evidence. Apply the [common release gates](../release-gates.md).

## Work packages

1. Specify BorrowedMut access regions and reject overlap with shared or exclusive access.
2. Add finite named typestate transitions through both Pythonic and explicit state APIs.
3. Represent mutation, consumption, escape and exceptional effects in summaries.
4. Validate state preconditions and normal/exceptional postconditions at call boundaries.
5. Treat await and yield as explicit boundaries for unsupported exclusive regions.

## Required exit gates

- [ ] **T01** — Known overlapping borrows and alias mutations during an exclusive region are rejected; unresolved exclusivity remains unknown.
- [ ] **T02** — Equivalent transition declarations lower to the same state machine, and invalid or contradictory declarations fail before flow checking.
- [ ] **T03** — A transition on only one branch creates a union of states; an operation requiring a single unmet state is diagnosed with appropriate certainty.
- [ ] **T04** — Exceptional state transitions follow explicit summaries and never inherit normal-return facts by default.
- [ ] **T05** — Unknown effects cannot be inferred as purity or no-raises; recursive summaries terminate under bounded analysis.
- [ ] **T06** — Exclusive borrows across suspension are rejected or reported unsupported according to mode; no thread-safety or race-freedom claim is made.

## Evidence to retain

State-transition tables, borrow-region counterexamples, effect-summary fixtures, API decision records and a documented strict-mode boundary matrix.
Complete a [release evidence record](../release-evidence-template.md) for the exact candidate revision. Link each gate to test results, fixtures, decisions or reviewed reports. A checkbox without evidence is pending.

## Hold and recovery policy

Finite typestate may progress while exclusivity remains experimental, but a declared required gate cannot be silently waived. Split or revise scope in the roadmap before release if necessary.
A failed required gate blocks the tag. Patch releases fix behavior within the published scope; moving a required feature out of scope requires a documented plan amendment.

## Deferred scope

Send/Sync analogues, lock proofs, arbitrary lifetime parameters and general effect polymorphism remain research.

## Release review

Review the phase gates together with G1–G8, publish limitations and changed diagnostics, then authorize the release tag separately. 0.6.x follow-ups retain these obligations and add regression evidence for each fix. See the [root roadmap](../../../ROADMAP.md).
