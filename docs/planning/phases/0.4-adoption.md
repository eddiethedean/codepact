## Outcome

A developer can introduce CodePact into an existing repository, record existing findings explicitly, and make CI fail on new actionable findings under a visible, reproducible policy. Human readers, external editor tools and CLI agents receive the same findings, certainty and coverage. An empty filtered report must never imply that unsupported code was checked successfully.

0.4 builds on the published 0.3 cleanup checker. It adds adoption policy and the initial synchronous must-use rule; it does not qualify task ownership, broader resource models, a language server or MCP delivery.

## Scope and deliverables

| Deliverable | Required bounded behavior |
| --- | --- |
| Project configuration | Validated `[tool.codepact]`, explicit source target, deterministic discovery/path/rule policies, and inspectable effective settings |
| CI policy | Advisory/strict modes, configurable severity threshold, preserved certainty/coverage and documented 0/1/2 exits |
| Reporting | Published checker JSON Schema, capabilities, source/configuration/model identities, stable ordering, bounded details and a location-per-line format |
| Adoption controls | Reasoned rule-specific line suppressions and explicit baseline generation; no suppression of execution failures or loss of coverage |
| Must-use | Equivalent `@must_use`, `MustUse[T]` and verbose metadata; bare synchronous discard, assignment, propagation and explicit `discard` semantics |
| CLI agent workflow | Rule explanations, bounded repair evidence, stale/truncated-result detection and opt-in check–edit–recheck instructions |
| Qualification | Three representative pilots including an async application, labeled triage evidence, clean onboarding, incremental/performance and exact-candidate distribution checks |

LE01 and the CLI portions of LE-V01/LE-V02 are mandatory reporting foundations. AI01–AI03 and CLI AI-V01–AI-V04 are mandatory through A08. CS02 enriches reports only with sites modeled by 0.3; unknown task/process handoffs remain boundaries. No TaskGroup lifetime violation or structured-task repair is required before CS03 qualifies that analysis in 0.5.

## Required exit gates

Existing IDs A01–A08 and CS02 are retained. All remain pending.

- [ ] **A01 — Reporting and exits.** Completed reports use documented policy-dependent 0/1 exits; invocation/configuration/execution failures use 2. Published versioned schemas, capabilities and text/JSON/concise fixtures agree on source locations, certainty, trust and coverage. Requires V04-02, V04-05–08, V04-18–19, V04-24–25 and CLI LE-V01/LE-V02.
- [ ] **A02 — Baselines and suppressions.** Only matching eligible existing findings are hidden from the actionable set. New rules, changed evidence, ambiguous identities and changed semantic settings remain visible. Updates require an explicit operation; suppression cannot erase coverage or failures. Requires V04-09–11, V04-20–21.
- [ ] **A03 — Configuration.** Invalid keys, types, targets, rule identifiers and schema versions fail clearly. Discovery, includes/excludes, physical containment and precedence have deterministic fixtures and inspectable effective values. Requires V04-01–04, V04-09, V04-24.
- [ ] **A04 — Must-use.** Decorator, alias and verbose annotation lower to equal result-use obligations. Bare synchronous calls, explicit discard, assignment, forwarding, symbol identity and unsupported async/dynamic boundaries follow the specification. Lightweight helpers remain typing-compatible. Requires V04-12–16.
- [ ] **A05 — Pilot usefulness.** Review at least three representative projects under the frozen [pilot protocol](0.4/pilots.md). At least 90% of at least 30 sampled definite-violation findings are actionable. Publish selection, counts, disagreements and remaining boundaries. Too few findings or missing evidence holds the gate. Requires V04-26.
- [ ] **A06 — Readiness and inherited correctness.** No supported-scope correctness blocker or unexplained frontend disagreement remains. Clean onboarding reaches a useful check, a verified supported repair and CI behavior; published docs and distributions match the candidate. Requires V04-03, V04-07, V04-13–14, V04-16, V04-18, V04-22–24, V04-26 and inherited V03 regressions.
- [ ] **A07 — Incremental policy correctness.** Source/target/model/rule/configuration/baseline changes refresh relevant findings, spans and coverage. Policy-only changes reuse semantic facts; fresh and reused sessions agree, with query-event evidence. Requires V04-10, V04-20–21, V04-24.
- [ ] **A08 — CLI agent foundations.** Complete AI01–AI03 and CLI AI-V01–AI-V04: structured evidence preserves certainty/coverage, detects stale/truncated output and demonstrates repair without weakening project policy. Requires V04-04–08, V04-15, V04-17, V04-19, V04-21–25.

If triage fails, keep experimental rules opt-in and rerun evaluation after semantic changes; reducing required scope needs an explicit roadmap amendment. Never lower certainty or relabel pilot samples to pass a target.

Structured task lifetime modeling begins in 0.5; LSP/editor clients, MCP services and persistent caches remain in 0.8. The optional TypePact combined product does not become a core adoption dependency.
