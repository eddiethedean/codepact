# 0.9 — Persistent obligations and before-and-after review

**Release 0.9.0.** This plan records the scope, release gates, and validation
requirements for persistent obligations and change review.

## Outcome

Track who still owes acknowledgment after an outcome is assigned or forwarded
and who still owes observation after submitted work finishes. Compare before
and after analyses to show whether a repair preserves the contracts and coverage
on which callers rely. Qualify the workflow with distinct HTTP and SQL models,
including supported concurrent requests and task-local database sessions.

## Entry baseline

Use published [CodePact 0.8.0](../../releases/0.8.0-evidence.md) for provider
identity, model selection, source-only analysis, installed author tooling and
runtime lifecycle behavior. Its OH01 and CR01 signoffs establish the outcome
production rules and review prerequisites. Phase 0.9 exercises those decisions
in the delivered workflows. Carry forward the released immediate `MustUse`
behavior and the existing package and Python support matrix.

## Implementation sequence

The [specification](0.9/specification.md) sets the proposed profiles and the
[validation matrix](0.9/validation.md) defines the release evidence. Provider
probes and a controlled wheel pair can be prepared alongside the first slice.

## 0.9.0 release gates

- **OH01** — Preserve immediate-use compatibility and qualify opt-in successful delivery, forwarding and renewal.
- **OH02** — Track carrier identity, aliases, temporaries, loss, exceptional evaluation and unknown storage.
- **OH03** — Qualify path-specific acknowledgment for finite variants, guards and wildcards.
- **OH04** — Apply per-exit helper effects and preserve the actual outward obligation through `finally`.
- **OH05** — Record reasoned discard, suppression and acknowledgment as distinct events or dispositions.
- **OH06** — Qualify direct-await delivery and intratask cancellation.
- **OH07** — Apply published outcome contracts and expose lost applicability, removed obligations and new waivers in review.
- **AS03** — Qualify local asyncio task and future observation and bounded `gather`, `wait` and `as_completed` membership.
- **MP03** — Qualify explicit-spawn Pool `AsyncResult` identity, readiness, waiting and observation.
- **BR01** — Qualify local thread-pool future identity, dispatch, cancellation and result/exception observation through executor exit.
- **LC05** — Qualify synchronous HTTPX and HTTPX2 independently, including mixed-environment controls.
- **LC07** — Qualify each direct-await HTTP profile with its own applicable artifact and AS07 evidence.
- **LC09** — Qualify synchronous SQLAlchemy ownership, settlement, session reuse, result consumption and cleanup.
- **LC10** — Qualify SQLModel `exec` and the exact-artifact ETLantic `session_scope` summary.
- **LC12** — Qualify the SQLAlchemy and SQLModel direct-await SQL profiles independently, including SQL result families and AS07 controls.
- **AS07** — Accept bounded shared HTTP client requests and task-local SQL sessions, diagnose overlapping operations on the same session and close during live use, and retain unknown boundaries.
- **E12** — Qualify opt-in declaration rules, preview and enforcement, baseline compatibility and strict incomplete-coverage behavior. [Gate definition](carry-forward-gates.md#e12)
- **CR01** — Capture normalized, versioned snapshots with comparable semantics.
- **CR02** — Report independent policy, scope, assumption and contract changes.
- **CR03** — Establish unambiguous finding and clean-site correspondence in the supported subset.
- **CR04** — Apply preservation prerequisites, verdict precedence and all blocking reasons.
- **CR05** — Qualify installed review, exit status, current-workspace validation and trusted CI inputs.
- **CR06** — Show parity across full selected-scope CLI and fresh and reused Rust analysis.
- **CR07** — Distinguish an accepted environment migration from a repair under preserved contracts.
- **CR08** — Refresh affected callers and show applicability changes on source-identical runs.
- **CR09** — Retain caller scope, unresolved siblings, exclusions and required budget limits.
- **E10-B** — Compare validated local wheel publications, covering compatible changes, new caller obligations, weaker guarantees and insufficient evidence. Qualify this installed author workflow and its parity independently of source review. [Checkpoint definition](carry-forward-gates.md#mandatory-e10-checkpoints)
- **E04** — Record exact upstream artifacts, runtime assumptions and maintained conformance fixtures for every new profile.
- **E05** — Qualify the helper, matching CLI extra, native CLI wheels, source archives and optional Cargo route.
