# 0.12 — Portfolio adoption, broader models and integrations

Status: **Planned; all new gates pending**. Target first release: **0.12.0**.
Owner: maintainer to assign before implementation. Legacy M5 integration/implementation Phase 5 commitments remain intact.

## Outcome

Qualify the expanded analyzer on selected large packages and expose the same evidence through caching, editors and agent tools. Broader framework/native support and richer carriers enter through named models and portfolio evidence.

## Dependencies and entry gate

Require the preceding semantic gates for every advertised model. Earlier cache/editor/MCP prototypes may be reused; they cannot bypass provider, obligation, revision or invalidation semantics.

## Required exit cases

- [ ] **E01–E10** pass in full under unchanged [definitions](carry-forward-gates.md#ecosystem-gates). **E10-C** completes supported-editor upgrade/shadowing parity and the composite E10 audit, retaining applicable E10-A artifact/author-workflow and E10-B artifact-comparison evidence. Earlier checkpoints were required in 0.8 and 0.9; they are requalified when affected, not deferred to this release.
- [ ] Requalify E11/E12 where provider, policy, cache or integration paths changed. Baseline disposition never waives strict incomplete coverage.
- [ ] **CS06** completes its original model matrix and CLI/editor/agent/fresh-cached scope with supported, invalid and unsupported process/thread controls.
- [ ] A named async I/O pilot and process-worker/ETL pilot each retain a useful defect/repair, correct control and boundary control. Record exact artifacts or complete named workspace scope, modernization profile, triage and cost.
- [ ] Field/cache cases distinguish created/injected ownership and cover aliases, lending, replacement, eviction, failed cleanup and reacquisition. Outcome fields preserve one duty through supported aliases/reads/replacement; unknown mutation retains a boundary.
- [ ] Native/framework evidence names actual provider/configuration and cleanup effects. A stub, context-manager shape, type annotation or related package cannot invent a lifecycle fact.
- [ ] Rapid edits, deletion, cancellation and rejected caches publish only current-revision results. Record cold/warm latency and peak memory; retain the original E06 regression threshold.
- [ ] All E05 artifact routes remain usable; optional dependencies and metadata cannot silently select another model family.

## Scope boundaries

Promote only named profiles. Portfolio rollout does not imply every backend, native variant, package or editor is supported. The ledger reports unqualified providers and missing caller scope even on runs without findings.

TypePact remains independently versioned. Resource-payload composition requires TC03 evidence. Research traits, arbitrary ownership and general thread/shared-state safety remain outside the supported claims.

## Evidence and release decision

Retain the exact candidate, model/provider artifact identities, selected Python/platform/start-method profiles, fixture IDs, valid/invalid/unknown cases, diagnostics/coverage, fresh/reused parity and costs in the [release evidence record](../release-evidence-template.md). Controlled upstream conformance fixtures are separate from static analysis; never import or execute the user's target project.

All required work and applicable [G1–G8](../release-gates.md) remain pending until evidence and the maintainer's decision establish completion. A missing gate blocks release or requires an explicit reviewed scope amendment. This plan does not authorize tagging or publication. Patch releases stay within the qualified 0.12.x scope.
