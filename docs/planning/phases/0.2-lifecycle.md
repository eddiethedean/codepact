# 0.2 — Mixed-interface lifecycle checking

Status: **Planned**. Target first release: **0.2.0**. No gate is currently marked passed.
Owner: maintainer to assign before implementation. Legacy mapping: M1 / implementation Phase 1.

## Outcome

Deliver the first useful end-to-end resource diagnostic.

## Entry gate

The preceding minor phase's required gates are accepted, or an explicit scope/dependency amendment has been recorded in the root roadmap. Reuse its supported corpus and baseline metrics.
Before work begins, turn the work packages below into issues with owners and acceptance evidence. Apply the [common release gates](../release-gates.md).

## Work packages

1. Extend the 0.1 declaration resolver and Salsa session with project discovery, supported re-exports and human-readable typepact check output.
2. Lower @resource and Borrowed parameters into the same shared engine, with declared or verified method summaries.
3. Track resource construction, normal close transitions, local aliases and branch joins.
4. Resolve supported calls across modules and expose unknown calls as analysis boundaries.
5. Explain diagnostics using both the invalid use and the state-changing operation.

## Required exit gates

- [ ] **L01** — The documented Connection example accepts inspect(conn) before close and reports exactly one use-after-close finding at the final call.
- [ ] **L02** — Closing through a local alias invalidates all tracked aliases; a branch that may close produces possible-violation certainty, not a definite-safe result.
- [ ] **L03** — Close-through-Borrowed is rejected within supported bodies, while valid non-consuming methods pass.
- [ ] **L04** — Shadowed API names receive no TypePact semantics; imported aliases and re-exports retain the correct contract.
- [ ] **L05** — Unknown calls and exceptional close behavior weaken facts and report coverage boundaries; no silent assumption of purity or an open state remains.

## Evidence to retain

Golden diagnostics, paired frontend snapshots, a runnable tutorial and a supported-pattern table. Capture cold analysis and runtime import baselines with machine/corpus metadata.
Complete a [release evidence record](../release-evidence-template.md) for the exact candidate revision. Link each gate to test results, fixtures, decisions or reviewed reports. A checkbox without evidence is pending.

## Hold and recovery policy

If alias tracking or exceptional effects cannot be resolved, narrow the declared supported subset and expose the boundary. Do not present lexical Borrowed access as a general lifetime proof.
A failed required gate blocks the tag. Patch releases fix behavior within the published scope; moving a required feature out of scope requires a documented plan amendment.

## Deferred scope

Leak detection, ownership transfer and general exception-aware cleanup are deferred.

## Release review

Review the phase gates together with G1–G8, publish limitations and changed diagnostics, then authorize the release tag separately. 0.2.x follow-ups retain these obligations and add regression evidence for each fix. See the [root roadmap](../../../ROADMAP.md).

## Analyzer architecture obligations

Add tracked CFG, function-summary and body-check queries; extend supplied-module resolution to project discovery and supported re-exports. Keep runtime instance/alias state separate from declaration identities. Define bounded recursive-summary recovery before accepting recursive calls.

Use the [shared architecture](../architecture.md) and [migration/query specification](../analyzer-migration.md). These obligations extend the existing phase gates.
