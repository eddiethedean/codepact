# 0.2 — Mixed-interface lifecycle checking

Status: **0.2.0 is being prepared; implementation is in progress and release qualification is pending.** All 0.2 gates remain pending. The prior 0.1.0 release is complete; see its [release evidence](../../releases/0.1.0-evidence.md).
Owner: maintainer assignment is not recorded in this plan. Legacy mapping: M1 / implementation Phase 1.

## Outcome

A developer can run `typepact check` on a small Python project and see a closed-resource use with both the use and close locations. The engine accepts the pre-close call and gives equivalent results for decorator and explicit metadata declarations.

0.2 checks lifecycle state through supported normal flow and local aliases, and rejects closing a Borrowed parameter within supported bodies. It does not establish ownership, uniqueness, general lifetime safety or cleanup on every exit.

## Scope and deliverables

| Deliverable | Required behavior |
| --- | --- |
| Project input | Explicit root and entry files; bounded local import discovery and acyclic named re-exports; no target-code execution |
| Flow model | Executable module statements and synchronous bodies; straight-line code, local assignment/rebinding, if/else joins and ordinary return |
| Resource state | Successful construction creates an abstract object; exact local aliases share state; uncertain targets require conservative updates |
| Calls | Resolved functions/methods use summaries with preconditions, normal effects, exceptional uncertainty and provenance |
| Borrowed access | Supported non-consuming methods pass; close through a borrowed parameter or local alias fails |
| Output and delivery | Human-readable check diagnostics, structured Rust results, one-shot/session parity, runnable tutorial and clean artifact smoke checks |

The source preview currently accepts `--json`, but checking JSON remains provisional until the phase gates pass. Configuration files, strict-mode switches, baselines and suppressions remain 0.4 work. Structured Rust results are required so text rendering does not become the semantic interface.

## Decision checkpoints

| Decision | Proposed bounded default | Acceptance requirement |
| --- | --- | --- |
| Discovery | Explicit root and deterministic local `.py` module map; no site-packages search; acyclic named re-exports | Define collisions, symlink containment and budgets; missing/added/deleted modules invalidate users |
| Alias domain | Construction-context object identities; strong updates only for exact targets, weak updates for uncertain target sets | Reassignment and branch joins cannot restore an invalid open proof |
| Summary trust | Infer supported ordinary bodies; apply declared close transition on normal return with declared-unverified provenance | No-op illustrative close does not prove runtime cleanup; unsupported ordinary bodies cannot imply purity |
| Exceptions | Separate normal effects from exceptional unknown; precise normal continuation only | No invented exceptional postcondition; handlers/finally expose boundaries pending 0.3 |
| Recursion | Detect recursive components before summary queries; initially recover to unknown effects and incomplete coverage | Bounded recovery, no query-cycle panic; accepting recursive effects later requires a fixed point/widening decision |
| Diagnostics/API | TP1001 closed use; proposed TP2001 close-through-borrow; existing TP4xxx/TP9xxx families | Freeze codes, assurance, certainty, deduplication, result versioning and exits before release snapshots |

Record accepted decisions with alternatives, fixture evidence, limitations and reconsideration triggers. No new helper API for repeat-close policy, exceptions or post-close permissions is required here.

## Required exit gates

- [ ] **L01 — Useful mixed-interface slice.** Connection accepts the pre-close call and emits exactly one definite TP1001 at the final call with the close location. Paired interfaces and Rust API/CLI agree. Requires V02-01–02, V02-19–20.
- [ ] **L02 — Aliases and joins.** Exact aliases share close state; rebinding detaches the place; distinct constructions remain independent. Conditional close yields possible certainty; uncertain targets cannot receive unsound strong updates. Requires V02-03–06.
- [ ] **L03 — Borrowed bodies.** Direct, aliased and transitive close-through-Borrowed fail in supported bodies; non-consuming methods pass. Unknown effects retain boundaries. Requires V02-07–08, V02-12–13.
- [ ] **L04 — Resolution.** Shadowed APIs receive no TypePact semantics. Imported aliases, explicit metadata and supported re-exports preserve contracts and callable identities. Discovery is deterministic and never executes source. Requires V02-02, V02-09–11, V02-18.
- [ ] **L05 — Conservative boundaries.** Unknown calls weaken reachable resource state and expose escape. Exceptional close, unsupported flow, recursion and budget exhaustion are visibly incomplete without fabricated open facts. Requires V02-12–13, V02-17–18.
- [ ] **L06 — Incremental correctness.** Callee effect edits update callers; unrelated edits reuse checks; location-only edits refresh related spans. Fresh/updated facts, diagnostics, certainty and coverage agree after source/discovery/settings changes. Requires V02-14–17.

## Hold and recovery policy

Hold for silent coverage loss, frontend disagreement, unsound alias updates, unknown calls treated as pure, stale summaries/locations, unbounded analysis or broken inherited inspection/installation. Do not present Borrowed access as a general lifetime proof. A reduced supported subset must expose its boundaries and preserve all required gates unless explicitly amended.
A failed required gate blocks the tag. Patch releases fix behavior within the published scope; moving a required feature out of scope requires a documented plan amendment.

## Deferred scope

Leak detection, owning cleanup duties, general exception-aware cleanup, loops, context-manager models, move enforcement, exclusivity, borrow escape/lifetime proofs and runtime enforcement are deferred. Repeat close without a declared policy remains unknown rather than introducing a double-close rule.
