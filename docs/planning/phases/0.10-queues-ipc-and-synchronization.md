# 0.10 — Queues, IPC and synchronization

Status: **Planned; all new gates pending**. Target first release: **0.10.0**.
Owner: maintainer to assign before implementation.

## Outcome

Check bounded protocols connecting producers, consumers and guarded resources. Carry responsibilities across reviewed queues and IPC while preserving the distinction between accounting, delivery, worker completion and cleanup.

## Dependencies and entry gate

Require 0.8 provider/process identities and 0.9 work/result obligation semantics. Select exact Python/platform/start-method profiles for every primitive. Version-specific APIs enter only the target profiles that qualify them.

## Required exit cases

- [ ] **AS04** pairs correct accounting with missing/duplicate acknowledgment, cancellation before/after acquisition and shutdown with unfinished work. A semaphore acquired inside many already-created tasks is not evidence that pending task creation was bounded. Immediate shutdown cannot turn bypassed accounting into proof of processed work.
- [ ] **AS05** pairs a valid guard with unreleased acquisition, unsupported release, cancellation during acquire/use/release and access outside a known guard. Unknown aliases/callbacks preserve incomplete coverage. Preserve valid awaits inside a reviewed async-lock scope; this does not waive the separate resource-exclusive-borrow rules.
- [ ] **MP04** distinguishes queue acceptance, feeder flushing, receiving, task accounting and process exit. Cover closed endpoint use, broken delivery, close/join-thread protocol, abandoned items and worker-local processing. JoinableQueue.join does not prove worker termination or result observation; Queue.join_thread concerns the local feeder protocol.
- [ ] **MP05** tests entry/importability and serializable plain-value controls under explicit spawn, then any independently promoted start profile. Cover local/unresolved targets, custom reducers, captured live resources, context mismatch, synchronization failure and compound shared-value updates without the required critical section. Synchronized property access alone does not establish an atomic compound operation.
- [ ] Sender/receiver identities remain distinct unless a qualified transfer model establishes more. Model/configuration edits preserve fresh/reused equality of facts and coverage.
- [ ] Before-and-after review exposes changed queue/guard contracts and newly unknown boundaries even when total finding count does not increase.

## Scope boundaries

These models check specific protocols, not global scheduler behavior. Accounting is not exactly-once processing or delivery. Declaring a lock does not prove all aliases obey it. Local checks do not establish global race/deadlock freedom, fairness or arbitrary atomicity.

Copied plain messages are not ownership moves. Shared-memory ownership, advanced shutdown and thread/executor bridges follow in 0.11. API availability on the checker host cannot qualify a different analyzed Python target.
