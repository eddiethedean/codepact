# 0.11 — Shutdown, async resources and executor bridges

**CodePact 0.11.0 source candidate.** Review the candidate evidence before
promoting the new profiles. Release acceptance and publication are pending.
[Implementation evidence](0.11/implementation-evidence.md)

## Outcome

Check bounded shutdown paths that leave work or cleanup behind. A shutdown
request, a completed wait, an observed result and a released resource each
need their own evidence. The checker should identify which duties survive
cancellation, failed startup or forced termination, and where the caller still
has a handle that can satisfy them.

## Entry baseline

Use published CodePact 0.10.0 for queues, IPC, guard checks and direct-script
spawn, and inherit 0.9.0 work identity, outcome acknowledgment, operation
leases and source review. The first profile uses CPython 3.13.16 on Linux
x86_64 with source target 3.13, standard asyncio scheduling and explicit
spawn for modeled Python workers. Each provider extension has its own pinned
profile and conformance evidence. Keep the published installation and
analysis-target matrix. [0.10.0 release evidence](../../releases/0.10.0-evidence.md) ·
[0.9 specification](0.9/specification.md) · [0.11 specification](0.11/specification.md)

## Release gates

- **AS06 and portfolio PC03** qualify the selected async generator,
  cleanup-context, stream, server and subprocess protocols. PC03 evidence
  here covers the async-resource subset.
- **Library LC07 and LC12** extend the existing HTTPX, HTTPX2, SQLAlchemy
  and SQLModel profiles with the named async result families and cleanup
  paths. Each provider must supply its own evidence.
- **MP06** qualifies partial worker startup, orderly and forced shutdown, and
  bounded shared-memory mapping, view and name lifetime.
- **BR02** qualifies named thread, process and event-loop bridges, including
  cancellation while underlying work continues.
- **Portfolio PC07** composes shutdown with retained task, IPC, work, result
  and cleanup duties.
- **E04** records pinned runtime and provider artifacts, applicability and
  maintained conformance fixtures. **E05** qualifies all inherited
  distribution routes.

## Scope and release decision

Limit claims to the named profiles. Unknown dispatch, escaped handles and
unreviewed finalizers produce incomplete coverage at affected operations.
Shared-memory checks establish a close and unlink protocol. Broader shared
state, field and cache ownership, and framework lifespans follow their
respective qualification plans. Publish repair guidance with the preconditions
for any proposed behavior change. [0.12 integration plan](0.12-ecosystem-and-integrations.md)

Record the exact candidate, applicability, fixtures, parity, costs and
remaining boundaries in the release evidence. The maintainer signs off
on the phase gates and G1–G7 before tagging. G8 records verified publication.
Missing evidence holds the release unless a reviewed scope amendment updates
all affected claims. Patch releases stay within the qualified 0.11.x scope.
