# 0.11 — Shutdown, async resources and executor bridges

Status: **Planned; all new gates pending**. Target first release: **0.11.0**.
Owner: maintainer to assign before implementation.

## Outcome

Compose shutdown and cancellation with work that can outlive its wrapper: async generators/streams, subprocesses, executor threads/processes and bounded shared-memory handles. Establish who must still wait, observe, close or unlink after partial failure.

## Dependencies and entry gate

Require 0.9's distinct completion/observation/acknowledgment duties and 0.10's IPC/guard protocols. Each bridge needs accepted dispatch, identity, normal/exceptional completion and cancellation semantics. Shared-memory profiles name exact Python/platform, resource-tracker behavior and lifetime owner.

## Required deliverables

| Work | Bounded delivery |
| --- | --- |
| AS06 and portfolio PC03 | Selected async generators, async cleanup contexts, streams/writers, server shutdown and asyncio subprocess protocols, including lazy acquisition, early abandonment, exhaustion and interrupted cleanup. |
| Library LC07/LC12 extensions | Expand independently qualified HTTPX/HTTPX2 and SQLAlchemy/SQLModel direct-await profiles with selected streaming/result families and advanced cancellation paths. |
| MP06 | Partial startup, worker failure, orderly/forced shutdown and bounded shared-memory mapping/view/backing-resource ownership. Name availability, close and unlink responsibilities stay separate. |
| BR02 | Named bridges such as to_thread, run_in_executor, wrapped concurrent futures and cross-thread coroutine submission. Dispatch timing, wrapper cancellation and underlying completion remain separate. |
| Portfolio PC07 | Compose shutdown with retained task/work/queue/result/resource obligations, including retryable or unknown cleanup. |

Canonical gates are [AS06, MP06 and BR02](../concurrency.md#new-stdlib-semantic-gates). An API outside an accepted profile stays explicitly unsupported.

## Required exit cases

- [ ] **AS06** covers unstarted generators, first-iteration acquisition, early break, explicit close, exhaustion and cancellation during finalization. Streams/subprocesses cover unfinished drain/wait, failure cleanup and termination requested without observed exit.
- [ ] Each async HTTP streaming and SQL result profile identifies its actual provider/result family. Context exit or a wrapper supplies no cleanup effect absent the reviewed model.
- [ ] **BR02** shows cancelling an await wrapper may leave a thread/process job running. Retain borrowed resources until underlying completion is established; cover timeout, cancellation failure, callback boundaries and queued versus running shutdown work.
- [ ] **MP06** covers partial startup, normal shutdown, forced termination, worker crash and outstanding IPC. A join establishes only its modeled completion, not successful work, observed failure or worker-local cleanup.
- [ ] Shared-memory evidence distinguishes each local mapping/exported view from backing storage and name availability. Cover existing versus later attachments, premature unlink, missing cleanup, retryable failure and tracker/manager/platform differences. Unlink can prevent a later attachment without closing existing mappings. Ordinary ownership annotations do not establish process isolation.
- [ ] Fresh/reused and before/after analysis preserve underlying-work identity and cleanup uncertainty after bridge, model and target-profile changes.

## Scope boundaries

No repair may add joins, shielding, cancellation suppression, termination, moves, unlink or close without verified behavioral preconditions. Cross-thread/event-loop legality and context propagation are supported only where the selected bridge describes them.

Shared-memory support is a bounded close/unlink protocol, not a proof of synchronized byte access, arbitrary shared object graphs or start-method equivalence. PC02 fields/caches and broader native/framework composition remain 0.12 promotion work.

## Evidence and release decision

Retain the exact candidate, model/provider artifact identities, selected Python/platform/start-method profiles, fixture IDs, valid/invalid/unknown cases, diagnostics/coverage, fresh/reused parity and costs in the [release evidence record](../release-evidence-template.md). Controlled upstream conformance fixtures are separate from static analysis; never import or execute the user's target project.

All required work and applicable [G1–G8](../release-gates.md) remain pending until evidence and the maintainer's decision establish completion. A missing gate blocks release or requires an explicit reviewed scope amendment. This plan does not authorize tagging or publication. Patch releases stay within the qualified 0.11.x scope.
