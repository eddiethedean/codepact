## Outcome

A developer can distinguish a resource that is closed or explicitly returned to an owner from one left unclosed on a modeled function exit. The checker follows cleanup through exceptions, early returns, loops and reviewed context managers, and reports where exceptional or cancelled cleanup remains uncertain.

0.3 adds cleanup duties to the published 0.2 lifecycle checker. It does not establish unique ownership, move validity, borrow lifetimes or task completion. Bounded intratask async cleanup is required by [CS01](../concurrency.md); structured task ownership remains 0.5 work.

## Scope and deliverables

| Deliverable | Required bounded behavior |
| --- | --- |
| Exit-aware flow | Explicit normal, return, raise, break, continue and cancellation outcomes; ordered evaluation and nested cleanup unwinding |
| Cleanup duties | One duty per successfully acquired local resource or explicit `Owned` parameter; aliases share it; borrowing does not create or consume it |
| Ownership return | A checked direct `Owned[T]` return hands the duty to the caller only on the final successful return; opaque escapes remain incomplete |
| Exceptions and contexts | Separate close outcomes; reviewed enter/exit, suppression, repeat-close and post-close policies; generic `with` gains no cleanup guarantee |
| Loops | Finite abstract object/obligation domain, monotone joins, bounded fixed points and conservative widening |
| Async foundation | Resolved direct coroutine awaits, captures, suspension, cancellation and awaited cleanup in one task; no TaskGroup lifetime qualification |
| Models | Versioned, source-only summaries for `contextlib.closing` and `contextlib.aclosing`, delegating to resolved resource cleanup; reviewed fixture models cover differing close outcomes |
| Delivery | Text/JSON/Rust-result parity, tutorials, limitations, model support table, incremental evidence and exact-candidate qualification |

No new runtime enforcement is required. Keep `resource(closed_by=...)`, `Resource`, `Owned` and `Borrowed` compatible and lightweight. Public syntax for exceptional effects, repeat-close policy and allowed post-close operations is not assumed; start with CodePact-owned model data and fixture summaries. Configuration modes, baselines and suppressions remain 0.4 work.

## Decision checkpoints

| Decision | Accepted default | Qualification evidence |
| --- | --- | --- |
| Duty origin | Successful local acquisition and explicit `Owned` entry create duties; ordinary resource parameters gain no implicit duty | Distinguish contract enforcement from uniqueness; do not double-count aliases or callee/caller views |
| Transfer | Only a resolved owning boundary can hand off a duty; an `Owned` return commits after cleanup unwinds | Return-expression failure, replacement return and close-in-finally fixtures; no inferred move proof |
| Exceptional state | Successful declared close discharges with declared-unverified trust; exceptional/cancelled state stays unknown unless modeled | Separate cleanup attempted from cleanup completed; use bounded built-in exception ancestry, preserve custom/unknown handler boundaries, and retain known violations alongside boundaries |
| Models | Use version-bounded `contextlib.closing`/`aclosing` and reviewed test summaries | Record exact Python versions/source revisions and conformance evidence before claiming support; no symbol-name matching |
| Flow limits | Retain unchanged 0.2 limits; cap total nested control-flow depth at 64, loop passes at 16, context-manager exit partitions at 256, tracked resources/duties at 4,096 and pending coroutines at 128 | Accepted under CL01 on 2026-11-07. ## Required exit gates

- [ ] **C01 — Exit obligations.** Diagnose an unclosed owned resource at each distinct modeled escaping path; test return handoff, lost aliases, certainty and duplicate grouping. Requires V03-01–03, V03-06–09, V03-13.
- [ ] **C02 — Cleanup outcomes.** Valid finally and reviewed context cleanup discharge duties on normal and modeled exceptional exits; failing close follows its exceptional postcondition. Requires V03-03–06, V03-10–12, V03-21.
- [ ] **C03 — Borrowing.** Borrowed inputs inherit no owner duty and cannot be closed directly, through aliases, helpers or context wrappers. Locally acquired resources still require cleanup. Requires V03-02, V03-09–11.
- [ ] **C04 — Joins and loops.** Conditional cleanup, early exits and loop-carried objects preserve uncertainty, allocation multiplicity and cleanup order; fixed points terminate within budget. Requires V03-05–06, V03-14–16.
- [ ] **C05 — Honest boundaries.** Unknown contexts, finalizers, effects, escapes and exhausted budgets never establish deterministic cleanup; affected duties remain unknown and coverage is visible. Requires V03-04, V03-08, V03-12–13, V03-16, V03-20, V03-23, V03-26.
- [ ] **CS01 — Intratask cancellation.** Meet the [shared gate](../concurrency.md): distinguish coroutine creation/execution, normal/raise/cancelled exits and interrupted cleanup; task handoffs remain boundaries. Requires V03-17–20, V03-22–26.
- [ ] **C07 — Incremental correctness.** Exceptional/cleanup/cancellation and model edits invalidate dependent obligations; fresh and updated results agree, including moved related spans and coverage. Requires V03-21–25.

Existing gate IDs are retained, including C07; the numbering gap does not create an additional gate.

## Hold, recovery and deferred scope

Hold for silently discharged duties, return transfer before finally, unknown cleanup treated as success, lost loop instances, stale model dependencies, frontend disagreement or unbounded work. A failed required gate blocks tagging; reducing required scope needs a recorded roadmap amendment and corresponding claim/fixture updates.

General task ownership/borrow regions, TaskGroup joins, detached/shielded tasks, generator finalization, arbitrary callback/container/field ownership, move enforcement, exclusivity and automatic close insertion are deferred. Process/thread handoffs are explicit unsupported escape boundaries. Existing recursive-summary recovery remains conservative. No race, deadlock, lifetime or runtime leak-freedom guarantee follows from a clean report.
