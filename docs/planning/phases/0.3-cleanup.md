# 0.3 — Cleanup and resource obligations

Status: **Planned**. Target first release: **0.3.0**. No gate is currently marked passed.
Owner: maintainer to assign before implementation. Legacy mapping: M2 part 1 / implementation Phase 2.

## Outcome

Follow owning resources through normal and exceptional exits.

## Entry gate

The preceding minor phase's required gates are accepted, or an explicit scope/dependency amendment has been recorded in the root roadmap. Reuse its supported corpus and baseline metrics.
Before work begins, turn the work packages below into issues with owners and acceptance evidence. Apply the [common release gates](../release-gates.md).

## Work packages

1. Extend CFGs with exceptions, finally, early returns, loops and context-manager cleanup.
2. Add resource cleanup obligations, explicit transfer on returned ownership and owning-versus-borrowing function distinctions.
3. Model close idempotency, exceptional outcomes and allowed post-close operations.
4. Introduce reviewed external resource summaries with version bounds and provenance.
5. Define widening and iteration budgets for flow analysis.

Concurrency work: Build bounded coroutine execution, suspension, cancellation and async context/close edges; distinguish coroutine creation from body execution. Qualify cleanup effects on normal, exceptional and cancelled paths before making intratask async claims. Follow [CS01](../concurrency.md) for the exact supported subset and evidence.

## Required exit gates

- [ ] **C01** — An unclosed owned resource is diagnosed at each distinct modeled escaping path, with duplicate reporting policy tested.
- [ ] **C02** — Valid finally and context-manager cleanup discharge obligations on normal return and modeled exceptions; a close that raises follows its declared exceptional postcondition.
- [ ] **C03** — A borrowing function neither inherits an owner’s cleanup duty nor gains permission to close it.
- [ ] **C04** — Conditional cleanup, loop-carried state and early return fixtures retain uncertainty at joins and terminate under the configured budget.
- [ ] **C05** — Unknown context-manager behavior and finalizers do not count as deterministic cleanup. Exhausted analysis budgets are visible in output.
- [ ] **CS01** — Complete the phase requirements in the [concurrent resource safety plan](../concurrency.md); retain valid, invalid and unsupported-boundary fixtures and fresh/reused parity for the claimed subset.

## Evidence to retain

An exit-path matrix covering each cleanup construct, model provenance records, regression fixtures and a report comparing full and bounded analysis.
Complete a [release evidence record](../release-evidence-template.md) for the exact candidate revision. Link each gate to test results, fixtures, decisions or reviewed reports. A checkbox without evidence is pending.

## Hold and recovery policy

Keep unmodeled cancellation and resource escapes visible. Delay a model whose behavior cannot be supported by evidence; a generic with statement cannot prove cleanup.
A failed required gate blocks the tag. Patch releases fix behavior within the published scope; moving a required feature out of scope requires a documented plan amendment.

## Deferred scope

General asynchronous ownership across tasks, exclusive borrows and automatic close insertion are deferred. CS01 adds only bounded intratask async cleanup; task ownership/borrow regions begin in 0.5.

## Release review

Review the phase gates together with G1–G8, publish limitations and changed diagnostics, then authorize the release tag separately. 0.3.x follow-ups retain these obligations and add regression evidence for each fix. See the [root roadmap](../../../ROADMAP.md).
