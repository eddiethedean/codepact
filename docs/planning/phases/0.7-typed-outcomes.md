# 0.7 — Typed outcomes and finite exhaustiveness

Status: **Planned**. Target first release: **0.7.0**. No gate is currently marked passed.
Owner: maintainer to assign before implementation. Legacy mapping: M5 runtime portion / implementation Phase 4.

## Outcome

Provide explicit result and absence values with predictable Python interoperability.

## Entry gate

The preceding minor phase's required gates are accepted, or an explicit scope/dependency amendment has been recorded in the root roadmap. Reuse its supported corpus and baseline metrics.
Before work begins, turn the work packages below into issues with owners and acceptance evidence. Apply the [common release gates](../release-gates.md).

## Work packages

1. Implement typed Ok/Err and Some/Nothing variants with documented payload, identity, equality and pattern-matching behavior.
2. Define generic variance from mutability and settle public Result/Option spellings.
3. Provide explicit nullable/Option and exception/Result adapters with lossiness documented.
4. Implement exhaustiveness for supported finite variants, accounting for guards and unreachable branches.
5. Connect outcome values to must-use contracts and ordinary checker compatibility.

Concurrency work: Qualify exception/outcome adapters around async work: cancellation and process-control exceptions propagate by default, and wrappers cannot discharge task or cleanup obligations. Follow [CS05](../concurrency.md) for the exact supported subset and evidence.

## Required exit gates

- [ ] **R01** — Runtime and pinned type-checker fixtures agree on construction, payload access, narrowing and generic assignment rules.
- [ ] **R02** — Conversions have round-trip cases and explicit lossy cases, including Some(None) versus absence.
- [ ] **R03** — Exception adapters catch only declared exception classes; cancellation and process-control exceptions propagate by default.
- [ ] **R04** — Guarded arms do not count as unconditional coverage; missing finite variants are diagnosed and valid exhaustive matches pass.
- [ ] **R05** — There is no implicit exception swallowing or automatic unwrap. Runtime variants integrate with both public namespaces without duplicate class identities.
- [ ] **R06** — Core resource and ownership fixtures still pass when outcomes carry modeled resources, or the unsupported composition is explicitly rejected.
- [ ] **CS05** — Complete the phase requirements in the [concurrent resource safety plan](../concurrency.md); retain valid, invalid and unsupported-boundary fixtures and fresh/reused parity for the claimed subset.

## Evidence to retain

Adapter behavior tables, runtime/checker compatibility results, finite-match fixtures, API reference and migration examples using native Python exceptions.

## Hold and recovery policy

Keep unsupported serialization and resource-payload compositions outside supported claims. Runtime convenience must not introduce a second ownership implementation.
A failed required gate blocks the tag. Patch releases fix behavior within the published scope; moving a required feature out of scope requires a documented plan amendment.

## Deferred scope

General algebraic data type inference and automatic framework serialization are deferred.
